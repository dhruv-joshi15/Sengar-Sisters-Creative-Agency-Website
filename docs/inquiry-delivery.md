# Inquiry delivery
The contact form submits to the local Next Route Handler `POST /api/inquiry`. On Vercel, set `RESEND_API_KEY` to a sending-access key and `RESEND_FROM_EMAIL` to an address at a domain verified in the same Resend account. The recipient is centralized in `data/siteData.ts` as `aditisengar1411@gmail.com`; the visitor's email is set as `reply_to`. Resend's [send API](https://resend.com/docs/api-reference/emails/send-email) and [verified-domain requirement](https://resend.com/docs/knowledge-base/how-do-I-create-an-email-address-or-sender-in-resend) are the implementation references. Never put the API key in a `NEXT_PUBLIC_` variable or commit it.

Without both environment variables, or when the provider errors, the form opens Gmail compose with all entered fields. The visitor must press Send in Gmail in this fallback path. A live provider send has not been exercised because no provider key/domain was supplied; a focused browser test verifies the Gmail draft locally. The server caps field lengths, validates required fields and uses a hidden honeypot field.
